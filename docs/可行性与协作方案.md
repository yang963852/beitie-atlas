# 碑帖之间：可行性与协作方案

调研日期：2026-11-17。当前交付为立项和开发方案，尚未开发网页、创建远程仓库或发布网站。

## 判断

**值得做，而且可以从很小的版本开始。工程上可行，长期质量主要取决于资料核实和持续维护。**

项目的第一句介绍可以是：在地图上找到现存碑刻和拓本，查看其身份、来历、已知流转与资料出处。

已经确认：碑刻为主、少量拓本；中国大陆读者优先，同时兼顾海外。第一版不承诺收录全部存世碑帖，也不把公开馆藏资料包装成实时位置服务。

英文适合代码、协作文档和国际交流，但不会自动改善浏览器兼容性或大陆网络访问。中文原名和别名从第一天保留；界面文字集中管理，以后可以增加中文界面。

## 从参考项目借鉴什么

[江山时序](https://github.com/DeanChensj/jiangshan-map)已经展示了地图、时间线、地点卡片和可分享链接的组合方式。我们借鉴这一交互思路，围绕实物的存续和流转重新设计数据。

暂不复制朝代疆域、古今行政区变化等复杂功能。那些功能既增加工程量，也增加历史地图考据工作。

参考仓库采用[GPL-3.0](https://github.com/DeanChensj/jiangshan-map/blob/main/LICENSE)。如果以后复用其中受许可约束的代码，需要保留许可并处理相应源码开放义务；不能一边复制，一边把整个衍生项目随意改成 MIT。当前建议独立实现，致谢灵感来源。

## 最关键的数据逻辑

“一件作品”和“一件实物”要分开。《颜勤礼碑》是一部作品，原石是一件实物，故宫收藏的民国拓本又是另一件实物。

[故宫官方馆藏页](https://www.dpm.org.cn/collection/impres/234175.html)明确其藏品是民国拓本，同时说明原石存于西安碑林。这正好检验网站会不会把两个地点混在一起。

每个实物至少回答：

| 问题 | 记录内容 |
| --- | --- |
| 叫什么？ | 中文原名、英文显示名、别名、对应作品 |
| 到底是什么？ | 原碑、摩崖、翻刻、拓本或残片；馆藏号；关联实物 |
| 怎么来的？ | 作者及其角色、形成时代、刻制或拓制背景、依据 |
| 现在在哪？ | 公开资料中的收藏机构或原址、位置精度、来源与核查日期 |
| 过去在哪？ | 分条历史事件、时间或时间范围、历史地名、来源 |
| 有什么不知道？ | 缺失年代、地点未知、归属有争议、历史中断 |

“网页核查于今天”不等于“馆方今天确认位置”。馆藏归属、实际存放地点、借展地点、是否可参观分别记录。未知的位置不能用收藏者籍贯、现代同名地或经纬度零值补齐。

第一版用现代底图表现有据可查的历史地点。历史连线只代表已知地点的先后关系，不能画成精确运输路线；没有证据的阶段留空。

## 第一版的功能边界

目标规模是约十部作品、十二至十五件实物，数量服从资料质量。先做三件实物的完整样例，再扩展内容。

1. 地图标记现藏机构或原址，同一馆的多个实物可以展开选择。
2. 列表与地图联动，支持中文名、英文名和别名搜索。
3. 基本筛选：时代、书体、实物类型、收藏地；不把作品时代误用为拓本制作年代。
4. 详情展示身份、来历、实物关系、现藏信息、时间线和出处。
5. 点击时间线节点定位到有证据支持的地点；不确定地点有明确标注。
6. 手机可用，选中实物可通过链接分享；底图加载失败时，列表与资料仍可阅读。

以后再讨论登录、评论、用户投稿后台、AI 问答、自动补全历史、高清图像对照、古代疆域、旅游路线和全量数据库。第一版用 GitHub 提交建议和纠错即可。

## 工程和发布选择

| 部分 | 当前建议 | 对你的意义 |
| --- | --- | --- |
| 网页 | React + TypeScript + Vite | 常见工具，便于模块化开发与检查 |
| 资料 | 仓库内的结构化文件，发布前自动校验 | 每次改动可查看、可审核、可回退 |
| 地图 | 先验证天地图官方接入；高德为备选 | 大陆访问优先，账户条件和实际体验通过后再定 |
| 地图组件 | 独立封装；若采用适配的标准底图，可用 Leaflet 稳定版 | 换地图服务时不用重写全部资料和页面 |
| 代码 | 计划放入你自己的 GitHub 公开仓库 | 所有人可以阅读、反馈、复制并依许可使用 |
| 网站 | GitHub Pages 可作早期候选；主站按大陆网络测试决定 | 开源地址和读者访问地址可以不同 |

[GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)支持静态网站，公开仓库可使用免费计划。但“代码托管免费”不能推导出大陆访问一定流畅，也不能推导出地图无限免费。

核心网页按静态站点设计，不设账号或业务数据库。若选高德，官方[安全密钥指南](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)建议生产环境使用服务端代理；这一成本要在地图选择时明确，不能把密钥放进前端文件后称为安全。

[OSM 公共底图](https://operations.osmfoundation.org/policies/tiles/)没有可用性保证，且不允许批量预取等用法，不把它当作大陆优先项目的无条件默认方案。地图署名、审图信息和服务条款按最终供应商要求保留。若以后使用大陆托管，再核对该服务要求的域名、备案等发布条件。

测试时分别检查网页、地图、字体和图片；电脑宽带与手机移动网络都要测，海外可用性另测。现在还没有这些实测结果。

## 开发阶段与验收

| 阶段 | 完成的事情 | 通过标准 |
| --- | --- | --- |
| M0：地基与访问试验 | 建工程、确定数据规则、接入一个真实地图、显示一个有来源的机构点 | 本机可运行；记录实际地图账户条件；你在大陆网络打开测试页面；无密钥泄漏 |
| M1：三个实物贯通 | 颜勤礼碑原石、其一册有编号拓本、另一件可靠碑刻 | 从地图进入详情和时间线；原碑与拓本不混淆；每项关键判断可回到来源 |
| M2：首版内容与体验 | 约十部作品、十二至十五实物；搜索筛选、手机、分享 | 全量资料校验通过；地图和列表一致；无位置资料仍能查看；分享后刷新正常 |
| M3：公开发布 | 代码、资料和媒体许可说明；贡献指引；自动检查；发布与回退 | 干净环境可运行；线上链接实测；发布版本可追溯；未通过的检查明确列出 |

“DeepSeek 说完成了”不作为验收证据。至少检查实际代码、运行页面、资料来源和失败情况。地图不可达、原碑拓本混淆、假坐标、无依据的确定历史、未授权图片或泄漏私密配置，都不能带到正式版本。

## 时间与费用

可以先利用现有电脑和免费公开仓库起步，当前不需要先买服务器、域名或 AI API。地图服务和最终主站是否收费，要在账户条款、额度及访问试验后决定，不承诺长期零成本。

建议先用一到两轮开发完成 M0，再用数轮迭代完成三个样本。首个公开版以“几周的小项目”作为规划尺度，不作为工期承诺；每天能投入多少时间、资料是否齐全、地图账号能否开通都会影响周期。最大持续投入通常是核实资料和维护，而不是写出页面。
