# 作品详情页改版：信息架构与验收标准

任务 D-003（2026-11-25）。本文件只定方案与验收，不改组件。现状依据 `src/components/KnowledgeLibrary.tsx` 的 `Entry` 与 [设计系统](design-system.md)。

## 1. 现状

作品页已由知识库统一渲染，顺序是：类别与审核状态 → 题名 → 年代与署名 → 编辑入口 → 导读（无导读时显示背景）→ 关联书家 → 传世实物（选择器、收藏地、事件、异说）→ 作品异说 → 关联作品与笔记 → 参考出处 → 页脚。

问题不在缺少字段，而在**层次按数据表排列，不按读者任务排列**：

1. 读者要判断“这是什么、值不值得临”，得先越过编辑入口和实物选择器。
2. “历史与流传”被拆在每件实物内部，逐件切换才能拼出全貌。
3. 没有临习入口。导读是一整段散文，读完后没有“下一步看什么、练什么”。
4. 审核状态只在页首出现一次，每件实物的状态混在元信息里，容易被略过。
5. 无导读、无实物、缺译、地图失败四种情况没有统一的空状态文案。

## 2. 改版目标

一个第一次到访的临帖读者，在不搜索、不点开实物的情况下，能在第一屏回答：这是什么作品、什么时代、什么书体、谁写的、现存什么、我该从哪里读起。第二次到访的读者，能直接跳到临习或版本。

不改数据结构也能完成第一版；七段式导读、字例图和版本对照依赖 [学习内容与媒体接口](learning-interface.md) 落地后再接入。

## 3. 信息架构

页首固定区（不可折叠）：

| 顺序 | 内容 | 数据来源 |
| --- | --- | --- |
| 1 | 类别、审核状态 | `review.state` |
| 2 | 题名（中英） | `titles` |
| 3 | 年代、日期含义、书体、署名 | `compositionDate`、`script`、`attribution` |
| 4 | 一句话定位 | `background`（现有背景段首句，不新写文案） |
| 5 | 页内导航 | 见下 |

页内导航用锚点，不用 JS 标签页：标题始终可见，链接可分享，键盘与读屏行为可预期。四个锚点：

1. **读作品**：导读；无导读时显示背景全文与“导读待补”的投稿入口。
2. **看版本**：实物选择器 + 选中实物的收藏地、存佚、事件、异说；保留“每件实物只显示自己的履历”的说明。
3. **理流传**：把选中实物的事件按时间列出，未知地点与断档显式留空；作品级异说放在此处，与实物异说分开。
4. **查出处**：来源列表、待考说明、编辑入口、GitHub 与下载链接。

移动端把四个锚点收进一行横向可滚动的目录；不使用抽屉，避免焦点陷阱。

## 4. 各区块的内容规则

- **读作品**：有导读时渲染导读全文，并显示“作品导读 · 待审/已审”；没有导读时渲染背景，并给出“本文尚无导读”的说明与投稿链接。不得用程序生成导读。
- **看版本**：每件实物显示类型、制作年代、存佚、收藏断言（含依据日期）。收藏地只显示来源所述，不推断展厅或库房；无坐标时保留文字。
- **理流传**：事件按日期排序，同一年内保持作者录入顺序；缺日期的事件排在末尾并标“年代待考”。事件地点缺失时写“地点待考”，不显示空白行。
- **查出处**：来源计数与展开后的条目数一致；草稿来源同样显示；外链使用 `rel="noreferrer"`。
- 所有界面文案进 `src/i18n/`，组件内不写学习内容或历史判断。

## 5. 空状态与降级

| 情况 | 页面表现 |
| --- | --- |
| 无导读 | 背景全文 + “本文尚无导读” + 投稿入口 |
| 无实物 | “本项目尚未收录可辨实物” + 仍显示导读与出处 |
| 无收藏地 | “收藏地待考”，不出现地图标记 |
| 缺英文翻译 | 显示所录中文并标 `lang="zh-Hans"`，不显示机器翻译 |
| 地图失败 | 收藏地文字、事件与出处照常可读，提供重试 |
| 减少动态效果 | 不使用滚动动画；锚点跳转即时到位 |

## 6. 验收标准

功能与内容：

1. 首屏在 1440×900 下可见题名、年代、书体、署名、审核状态与页内导航，无需滚动。
2. 四个锚点可直接分享；刷新 `#/work/liqi-bei#kan-banben` 后停在“看版本”，焦点落在该区标题。
3. 用键盘 Tab 可依次到达导航、各区块标题、实物选择器、来源链接；焦点环 2px 可见。
4. 当前 `index.html` 只有 `<div id="root"></div>`，没有 `noscript` 说明。改版需补一段静态说明与 GitHub 入口，或在验收记录中明确写“未启用 JavaScript 时页面为空”，不得把缺口当成通过。
5. 草稿与已审在同一页并存时，各自标签不合并、不互相推断。

视觉与响应式：

6. 390、768、1440 三个宽度与 200% 缩放下无横向溢出，正文行宽不超过 38rem，控件不小于 44×44 CSS px。
7. 页内导航在 390 下可横向滚动且不遮挡正文；滚动时标题不被固定栏遮住。
8. 颜色之外还有文字或图标表达审核状态与存佚，符合 [设计系统](design-system.md) 的无障碍要求。

性能与回归：

9. 首访传输字节与详情打开耗时以任务 044/048 的基线为准，改动后同一设备、同一网络复测，记录实测值；不得只贴构建体积。
10. `npm.cmd run check` 全通过；新增交互有针对性测试，不为配色选择写测试。

内容前提：

11. 七段式导读、典型字例与版本对照在接口落地前不显示空壳区块；宁缺不假。
12. 任何新增的学习建议、审美判断必须标注审读者；未审读者显示“待专业审读”。

## 7. 实施顺序

1. 页首固定区与页内导航（纯前端，不动数据）。
2. 空状态与降级统一（纯前端）。
3. 接入 `guide.sections` 与字例媒体（依赖接口方案第 4 节）。
4. 版本对照（依赖媒体 `role: comparison` 与实物关系）。
5. 关联推荐与学习路径入口（依赖 topics 与 learning）。

第 1、2 步可以在接口批准前单独交付；第 3 步以后必须等编译器支持，避免先做壳后返工。

## 8. 非目标

不引入路由库、状态管理库或组件库；不做登录、收藏、进度记录；不把导读改成视频或交互课件；不为未收录的实物生成占位图。
