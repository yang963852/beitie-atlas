# 地图怎么做：六种方案与取舍

最后更新：2026-11-18。本文回答两个问题：底图用哪家，以及**为什么现在地图上看不到点**。

## 一、先分清两件事

地图看起来是“一个功能”，实际是两条独立的链路：

| 链路 | 现在状态 | 卡在哪 |
| --- | --- | --- |
| 底图（瓦片、缩放、样式） | 代码已完成，未接真实服务 | 缺一个服务商密钥 |
| 点位（15 处地点只有 2 处有坐标） | 13 处明确记为“暂无点位” | 缺**可引用的坐标证据**，不是缺技术 |

只解决底图，地图上仍然是 2 个点。只解决坐标，没有底图就只能看列表。**两件事都要做，但顺序应是先坐标、后底图**，否则会得到一个漂亮却几乎空白的全国地图。

## 二、六种底图方案

| 方案 | 密钥 | 坐标基准 | 合规（中国大陆公开站点） | 成本 | 离线 | 判断 |
| --- | --- | --- | --- | --- | --- | --- |
| **天地图** JS API 4.0 | 需注册申请 | CGCS2000（与 WGS84 差异在厘米级） | 国家测绘系统平台，底图自带审图号 | 免费额度内 0 | 否 | **主选**，代码已适配 |
| 高德 JS API 2.0 | key + 安全密钥 | GCJ-02 | 有审图号，须遵守服务条款 | 免费额度 + 商用授权 | 否 | 备选，视觉更好但要多一层坐标转换 |
| 腾讯地图 JS API GL | key | GCJ-02 | 同上 | 同上 | 否 | 微信生态内可选 |
| 百度地图 JS API GL | key | BD-09 | 同上 | 同上 | 否 | 不推荐，多一次偏移换算 |
| OSM / 自建瓦片 + Leaflet | 无 | WGS84 | **不合规**：无审图号，不能作公开底图 | 服务器与流量 | 可以 | 仅内网或研究用 |
| 无底图示意 | 无 | WGS84 | 不构成“地图”，无需审图号 | 0 | 可以 | **永久保留的降级形态** |

三条容易被忽略的约束：

1. **坐标系不是小事。** 本项目只存 WGS84。高德、腾讯、百度都要在渲染时把 WGS84 转成 GCJ-02 或 BD-09。转换只能单向：可以把真实坐标偏成火星坐标，不能把火星坐标还原。因此转换必须发生在视图层，数据层不许写回。
2. **审图号是法律要求，不是风格问题。** OSM 数据本身很好，但在中国大陆公开网站上作为底图使用没有合规路径。这也是项目的来源白名单只允许天地图、腾讯、高德、百度四家的原因。
3. **密钥不能进仓库。** 前端密钥写进 `.env.local`，该文件已在 `.gitignore` 里；构建产物里出现密钥等同于公开。

## 三、推荐路线

**天地图做主底图，无底图示意做永久降级。** 理由：

- 代码层面已经写好适配器（`src/map/tianditu.ts`），换服务商等于重写这一层；
- 坐标基准与数据一致，不需要偏移转换，少一类错误；
- 底图自带审图号，公开部署时不必再单独送审底图；
- 拿不到密钥、或密钥限额用尽、或被网络阻断时，降级面板仍然给出完整可读的地点列表——这是已经实现并有测试覆盖的行为。

**高德作为备选**，只在一种情况下值得换：需要更强的移动端交互或自定义样式。换的代价是要新增一层坐标转换，并在界面上标注“底图为 GCJ-02，点位已按公开算法转换”。

## 四、真正的工作量在点位

15 处地点里 13 处没有坐标，原因不是没查，而是查到的坐标达不到项目要求：

- 维基数据的 P625 返回值被四舍五入到 0.01°（约 1 公里），把这种精度标成“机构点位”是虚报；
- 馆方页面通常只给地址，不给经纬度；
- 项目要求每个点位有 `sourceRefs`、`precision`、`method`、`verification` 四项齐全，缺一项就不能画。

可扩展的路径只有一条：**用服务商的地理编码接口反查机构坐标**。数据模型里已经预留了 `method: 'geocoder'`，配套约定是：

- `precision: 'institution'`，`verification: 'unverified'`；
- `note` 写明“由 XX 地理编码按机构名返回，未实地核对”；
- 同一机构多次编码结果不一致时，取稳定值并记录差异。

这条路同样需要密钥——所以**一把钥匙同时解锁底图和 13 个点位**。这也是任务 004 一直挂在“等待业主提供密钥”的原因。

## 五、三个阶段的动作

**阶段一（不需要密钥，现在就能做）**

- 把降级面板从“地点列表”升级为“覆盖率说明”：多少处有点位、多少处没有、为什么没有；
- 保证每个无点位记录在列表里可被检索到，而不是从地图上消失。

**阶段二（拿到天地图密钥后）**

- 按 [map-setup.md](map-setup.md) 申请「浏览器端」Key，写入 `.env.local`，先用
  `npm run check:map-key` 确认服务端接受这个 Key，再打开页面；
- 验证底图、缩放、点位聚合；
- 对 13 处机构跑地理编码，逐条补坐标与来源；
- 用真实截图替换 README 中的降级界面截图。

**阶段三（数据稳定后）**

- 加时间轴：同一地点在不同朝代的状态变化；
- 点位聚合按“朝代”而非“城市”分组，与列表的排序保持一致。

## 六、结论

地图不是“选一家服务商”的问题，而是**证据链**的问题：底图要有审图号，点位要有可引用的坐标，两者都不能靠猜。当前代码已经把“没有证据时不画点”做成了默认行为；剩下的是拿到密钥、补足坐标，而不是重写地图。
