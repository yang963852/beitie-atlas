## 二、发现并修复的缺陷

### 1. 地图在降级面板的高度里初始化（真实缺陷）

`.map--fallback` 的高度是 210 px，而地图组件在「加载中」时也套用了这个类。SDK 只在
`new T.Map(container)` 时量一次容器，之后容器长到 734 px，它仍按旧尺寸加载瓦片——
表现为地图只占上半栏、下面一片灰。

修复两处：

- `MapPanel` 只在**未配置**时使用 `map--fallback`；加载中与已就绪都用满高布局。
- `createTiandituAdapter` 挂载 `ResizeObserver`，容器尺寸变化时调用 SDK 的
  `checkResize()`；销毁时断开。新增回归测试覆盖「观察容器 / 触发重算 / 销毁断开」。

### 2. 测试被本地密钥污染（真实缺陷）

`.env.local` 存在后，两个应用测试从「未配置地图」变成「加载中」，断言失败。
这不是数据问题，而是测试依赖了开发机的环境。修复：`vite.config.ts` 的 `test.env` 强制
`VITE_TIANDITU_KEY` 为空，让测试固定覆盖未配置路径；适配器路径由独立测试覆盖。

### 3. 自检命令把「浏览器端 Key」误报为失败

`301012` 的真实含义是「这是浏览器端 Key，服务端接口按设计拒绝」。原实现按普通拒绝处理，
会让人以为 Key 坏了。现在单独识别：输出「Key 类型正确（浏览器端）」，退出码 0，并提示去
浏览器验证。命令行无法验证浏览器端 Key 这件事，也写进了 `docs/map-setup.md`。

### 4. 手机端「显示全部点位」被挤成两行（真实缺陷）

390 px 下按钮随文字收缩，变成「显示全 / 部点位」。修复：按钮 `flex: 0 0 auto` +
`white-space: nowrap`，标题区让出宽度。复测后保持单行，画布 356×454。

## 三、瓦片协议

本地开发页是 `http://localhost`，所以瓦片请求是 `http://t0…t7.tianditu.gov.cn/...`。
SDK 内部按 `document.location.protocol` 选择协议（`T.Protocol`），https 页面会请求 https
瓦片，因此生产环境不存在混合内容问题。本轮没有部署 https 站点，这一点仍属**代码层结论**，
不是线上实测结论。

## 五、下一步：补 13 处坐标需要另一个 Key

本轮确认：**浏览器端 Key 不能调用服务端接口**，包括地名搜索/地理编码（返回 `301012`）。
因此「用同一个 Key 批量补坐标」这条路走不通。两个可选方案：

1. **再建一个「服务端」应用**（同一账号可建多个应用），用它的 Key 调用地理编码接口，
   在服务端批量查询 13 处机构；结果按 `precision: institution`、`verification: unverified`
   写入，并在说明里注明「服务商地理编码，未实地核对」。
2. **逐处找可引用的点位来源**（馆方页面、政府公示、测绘成果），慢但证据更强。

无论走哪条，坐标都必须带来源与精度，不能因为「有 Key 了」就撒点。
