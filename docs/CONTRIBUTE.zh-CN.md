# 中文投稿与试读指南

[项目首页](../README.md) · [知识库目录](../knowledge/README.md) · [网站 · 1.1 版](https://yang963852.github.io/beitie-atlas/)

## 直接提 PR

欢迎直接修改文章、资料或代码。PR 是把你的修改交给维护者审查的地方，无需预先开 Issue，也无需申请仓库写权限。主要审查人和维护人是 [@yang963852](https://github.com/yang963852)。

- **只改一篇文章**：按下方的浏览器步骤操作。
- **改代码或多个文件**：从本仓库创建 Fork，在自己的分支完成修改后打开 **Compare & pull request**。目标仓库选 `yang963852/beitie-atlas`，目标分支选 `main`，来源选自己的 Fork 和修改分支。说明改了什么、怎样核对，即可提交。后续修改继续推送同一分支。

## 直接编辑一篇文章

从[知识库](../knowledge/README.md)进入署名文章，点 GitHub 文件右上角的铅笔，修改正文或附上来源，再切到 **Preview** 检查。点 **Commit changes**，选择创建分支并提交 **Pull request**；首次参与时按 GitHub 提示创建自己的 Fork。在 PR 中写明改了哪一句、依据在哪里。若编辑的是标有「生成」的目录或实物资料，可在 PR 中修改对应的来源记录，并按下文更新生成页。只掌握线索时，也可以用资料投稿表附上该页链接。

读帖观察欢迎中文原稿。请写明观察人、具体版本、哪一字或哪一行、别人怎样复看。第三方图片可给原始链接；申请收录图片时附作者、来源、许可和署名方式。保留相冲突的著录和各自出处。一般投稿只走一条路径即可。

想新写一篇，可以在 [作品](../knowledge/works)、[书家](../knowledge/people)、[读帖笔记](../knowledge/notes)或[实物](../knowledge/objects)目录点 **Add file → Create new file**，用小写英文字母、数字与短横线起一个便于引用的文件名，以 `.md` 结尾。先复制对应的[中文模板](../knowledge/_templates/)，把 `schemaVersion: 2` 保留在顶部。作品与实物的日期、署名、出处和审核状态写在 YAML；背景、待考和导读写进正文。参考[现有作品](../knowledge/works/yan-qinli-bei.md)，正文用下列结构：

```markdown
---
schemaVersion: 2
titleZh: 作品题名
studyCategory: bei
dynastyId: tang
dateKind: single
dateStart: 779
dateEnd: 779
dateCertainty: documented
attribution:
  - role: author-and-calligrapher
    name: 姓名
    certainty: documented
    sources: [src-example]
sources: [src-example]
reviewState: draft
reviewNote: 还缺什么证据
---

# 作品题名

## 背景

### 中文

……（有英文译文时放在 `### English`）

## 待考

### 中文

- ……（可省略译文，不要机器翻译）
```

没有署名时写 `role: unknown`，不要留空。日期没有来源时留空并在待考说明，不猜年份。

新建、改题或调整审核状态可能使知识总目需要更新。编辑可在同一投稿 PR 运行 `npm run knowledge:compile && npm run knowledge:generate` 并提交生成结果；如果投稿人使用 Fork，由编辑与投稿人协商分支更新或关联整理 PR。你可以始终只用浏览器。

## 来源六条硬规则

| 材料 | 可否引用 | 记录方式 | 常见误用 |
| --- | --- | --- | --- |
| 博物馆、图书馆、文物机构、政府页面 | 可 | `kind: web`，URL、发布者、查阅日期、段落或馆号 locator | 把机构页的概述当成保存状况调查 |
| 印本图录、拓本汇编、考古报告 | 可，须实际见到该书 | `kind: book`，出版者、年份、页码或条目号；不编 URL | 只见书名就补页码 |
| 书论、题跋、金石著录 | 可 | 作者、篇名、卷次；转引须写“转引自” | 把转引写成亲见原书 |
| 教学资源、课程记录、公开课 | 限于它所记录的那次使用 | 机构、课程、日期、段落 | 用一次课程证明“通行教法” |
| 碑帖 App、论坛、百科 | 不可作证据 | 只作线索，用来发现碑名与别名 | 用条目里的年份、尺寸支撑断言 |

1. **一条断言一条来源**。同一段里的事实句，逐句能回到 `sources` 中的某条；找不到就删句或写“待考”。
2. **locator 要能落到段、页、馆号**。“该网站有介绍”不算 locator。
3. **查阅日期不是核验日期**。`accessedAt` 只说明哪天打开过页面；原石的保存状况、展厅位置、拓本真伪，未核实就写未核实。
4. **冲突并列，不取平均**。年代、尺寸、行款、作者出现两说时，两说都写，结构化字段留空或取有明确出处的一说并注明异说。
5. **转引分层**。原书、整理本、二手转述分开写；二手转述只能支撑“某人如此说”，不能支撑“事实如此”。
6. **图版与授权**。用馆方图版要记编号或页面；不用来源不明的扫描图；不把图版裁切后当作“原石细部”。

馆藏著录解决“在哪里、是什么、多大、几行”；书论题跋解决“历来怎样评、谁说过”；学术文献解决“为什么这样看、有没有异说”。三者不能互相替代。

## 导读七段规范

作品导读不是独立文件，而是作品 Markdown 的 `guide*` 前置字段加正文 `## 导读` 段落。现有 schema 只承载导读的状态、时间轴年份、关联人物、关联实物与来源；七段是正文编辑规范，用 `####` 标题写在 `### 中文` 与 `### English` 之内，不新增字段。

### 记录头

```yaml
guideState: draft          # 审读前一律 draft
guideTimelineYear: 156     # 有时间轴意义的年份，整数
guidePeople: []            # 正文实际提到的人物 id
guideObjects: []           # 正文实际引用的实物 id
guideSources: []           # 正文全部外部事实的来源 id
```

### 七段与各段要求

| 段 | 写什么 | 所需证据 | 可留待考 | 审读 |
| --- | --- | --- | --- | --- |
| 01 概述 | 作品是什么、谁在何时为何而作、内容、书体形制、今在何处；第二段回答“为什么现在读它” | 馆藏著录的定名、别名、年代、撰书人、行款、尺寸、额与四面；原址与现藏 | 撰书人无考写“未署名”并说明来源如此；尺寸、行款、碑额各说并列；移置细节归 02 | 以事实为主；写“历来被视为某体代表”须随即给出提出者与出处 |
| 02 历史与流传 | 刻立、原址、移置、损泐、拓本谱系、鉴藏印记、历代著录；按时间顺序，作品／原石／拓本三种对象分开 | 政府或馆方移置记录；图录的题签、藏印、装裱与册页形制；金石著录的书名、卷次、条目 | 只知“约某年”写约；拓本先后无法判定写“待比勘”；未见原书标“待访” | 递藏链每一手要有名字或印记，缺一环就断开，不用“相传”接续 |
| 03 作品赏析 | 书体与结字、章法与行气、书写与刻工、历代品评及依据；先给可核观察，再给评价 | 书论原文（作者、篇名、版本或转引层级）；馆方图版编号或印本页码；对照对象须已收录或注明出处 | 图版不足的细节；两家评语矛盾时并列；刻工改动无法区分时明说 | **全部审美评价须由有书法实践的人审读**；项目判断写 `> 待专业审读：`，古人评语照录署名 |
| 04 典型字例 | 三至六个字例：字、面与行（或图版页）、结构观察、临写要点、选它的理由；覆盖不同结构类型 | 能指到同一字的馆藏图版或印本页码；原石与拓本的字口差异；损泐状态 | 行数或字位不确定写“行数待核”；未见图版不描述点画；只在一件拓本见到的特征不写成原石特征 | 结构分析与临写要点整段须专业审读；未审读只写位置与字形 |
| 05 临习指南 | 选本、读帖顺序、日课、阶段目标、常见问题与自检；先教看，再谈写 | 可得印本或图版信息；有出处的临习传统；公开教学记录 | 字帖版本、课时、工具可留待补；无教学记录的“入门推荐”只能作建议并标审读 | **整段须由有书法实践的人审读后发布**；不写“必须”“唯一”“几天见效” |
| 06 延伸学习 | 同书体、同时代、同地域或同礼制背景的对照；可继续查的馆藏、展览与研究；每条写“为什么对照、看什么” | 本项目已收录可链接的 id；馆方展览页或图录；学术综述 | 未收录写“待收”，不建空链接；展览是否仍在展出须核当时状态 | 对照中的风格判断按 03 处理；只列顺序、不下高下的可免审读标记 |
| 07 研究与文献 | 著录、题跋、论文、图录，按“原书—转引—本项目来源”分层；每条给作者、篇名、卷页、出版信息 | 馆藏著录页；书论篇名；金石著录卷次；论文期刊、年份、页码 | 出版年、出版社、页码未核留空标“待访”；不编 DOI、ISBN、馆藏号 | 不需书法审读，但需一次书目核对：作者、篇名、卷页不能互相矛盾 |

### 写作细则

- 中英成对：`### 中文` 与 `### English` 各写一份七段，英文是中文的翻译，不增事实，不是机器翻译占位。
- 冲突并列，不取平均；结构化字段留空，冲突写进当段与 07。
- 每句事实给链接或“作者《篇名》卷/页”；转引写“转引自”，不伪装成亲见原书。
- `guidePeople`、`guideObjects`、`guideSources` 必须与正文实际引用一致，id 真实存在。
- 审读前 `guideState: draft`；审读后由审读人确认再改 `guideState: reviewed`，实施者不能自审自批。

## 下载完整知识库，改一篇再提 PR

[下载完整知识库 ZIP](https://yang963852.github.io/beitie-atlas/download/beitie-knowledge.zip)。压缩包随已检查的 `main` 生成，附源提交号、中文总目、作者 Markdown、生成目录、内部链接和权利说明。

1. 解压，用 Obsidian 或任意 Markdown 编辑器打开。先读根目录的 `开始阅读.md`。
2. 只改你要改的那一篇，例如 `knowledge/works/yan-qinli-bei.md`。文件名是稳定 ID，不要改名。
3. 在自己的 GitHub Fork 中按原路径上传这个文件，向 `yang963852/beitie-atlas` 的 `main` 提 PR。
4. 只提交你改动的源稿。`knowledge/catalogue/`、`knowledge/README.md` 和 `manifest.json` 是生成文件，由项目维护者重新生成。

## 只用浏览器提交资料

1. 登录 GitHub，打开[资料投稿表](https://github.com/yang963852/beitie-atlas/issues/new?template=knowledge.yml)。题目写「作品或人物＋想补充的事」。
2. 用自己的话写一件事。馆藏网页附链接和段落，书刊附作者、书名、版本、页码或图版。只知道线索时，在出处栏写「待查」，说清哪一点有疑问。
3. 点 **Create** 提交，记下弹出的 Issue 编号。资料编辑在原帖认领，回帖附整理后的条目、PR 链接、待补证据或暂缓收录的理由。署名可用 GitHub 名或笔名。

例如，故宫藏《颜勤礼碑》拓册的馆藏号为「新00045406」。如果要补制作年代，可以写「故宫藏品简介著录为民国拓本，具体拓年待考」，注明该页的对象名称、简介段和链接。把这条证据归给故宫这件拓册，原石另有自己的经历。[故宫藏品著录](https://www.dpm.org.cn/collection/impres/234175.html)

## 五分钟试读

1. 打开[网页知识库](https://yang963852.github.io/beitie-atlas/#/library)，找到[颜真卿](https://yang963852.github.io/beitie-atlas/#/person/yan-zhenqing)，从书家页进入[《颜勤礼碑》](https://yang963852.github.io/beitie-atlas/#/work/yan-qinli-bei)。刷新一次，看看能否回到同一条目。
2. 打开作品下的一件实物，找它的持藏出处。换到另一件，对比实物名称、年代和记载。再回知识库，选择「书家」，搜「沈尹默」，查一条与他有关的人物关系及所附依据。
3. 任选手机或电脑，试试键盘 Tab、浏览器返回或放大页面。遇到问题点[反馈问题](https://github.com/yang963852/beitie-atlas/issues/new?template=beta-feedback.yml)，写下出问题的网址、设备或浏览器、操作步骤、实际结果和预期。也欢迎告诉我们哪段叙述最难读。

目前人物与作品专题按选题逐步增加，条目以馆方与印本著录为据；部分年代、藏址与当代临习使用情况仍待来源核实。真实底图依赖网络和地图服务；没有坐标的实物仍可查阅文字、来源和已知地点。各地网络能否打开须在当地实际测试。网站读者都能打开这个公开的 Pages 地址；「1.1」指本次内容版次。
