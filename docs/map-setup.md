# 开通地图：给项目所有者的一步步说明

这份说明写给不写代码的项目所有者。目标只有一个：拿到一个天地图「浏览器端」密钥（Key），
让本地预览显示真实地图。**不需要改代码，也不需要在对话里发送 Key。**

技术背景和来源核查在 [map-pilot.md](map-pilot.md)。本文只讲你要做的事。

---

## 1. 你需要准备什么

- 一个能收短信的手机号和一个常用邮箱。
- 大约 10 分钟。
- 不需要付费：截至 2026-11-17，天地图官方 JavaScript API 页面写明「免费对外开放」。商用授权
  和高用量配额本次没有核实。

官方入口：<https://www.tianditu.gov.cn/>（右上角「注册」）。
开发文档：<https://lbs.tianditu.gov.cn/api/js4.0/guide.html>，其中写明「使用API之前，需要申请应用Key」。

## 2. 申请密钥（在天地图控制台操作）

下面这些菜单名称来自公开资料和官方页面。控制台需要登录，本次实现没有实际走完整个流程，
所以**如果看到的名字略有不同，按意思找最接近的入口**，不要因为少一个按钮就停下来。

1. 打开 <https://www.tianditu.gov.cn/>，点右上角「注册」，用手机号和邮箱注册。
2. 登录后进入「控制台」（有的页面写作「开发资源 → 控制台」）。
3. 按提示「申请成为个人开发者」，阅读并同意服务条款。个人开发者即可，不需要企业资质。
4. 进入「应用管理」或「我的应用」，点「创建新应用」。
5. 填写应用名称（例如 `beitie-atlas-local`）和行业类别。
6. **应用类型必须选「浏览器端」**。选成「服务端」会导致网页里调用失败。
7. 域名白名单：
   - 本地调试可以先留空（是否允许 `localhost` 未核实；留空通常表示不限制）。
   - 正式上线前必须填写真实域名，否则别人可以盗用你的配额。
   - 多个域名一般用英文逗号分隔；是否支持通配符请在控制台确认。
8. 提交后，在应用列表里复制生成的 Key。它是一串字母和数字。

如果卡在实名认证或某个页面，把**页面截图**留下（遮住身份证号等个人信息），不要发账号密码。

## 3. 把 Key 放进项目（不改代码）

1. 打开项目文件夹：`C:\Users\zhangyang\Desktop\AI_working\碑帖之间`
2. 在根目录新建一个文本文件，文件名必须是 `.env.local`（注意前面有一个点，没有 `.txt` 后缀）。
3. 文件里只写一行：

   ```
   VITE_TIANDITU_KEY=你的Key
   ```

   等号两边不要加空格，不要加引号。
4. 保存。`.env.local` 已经被 `.gitignore` 忽略，不会进入 Git。
5. 在项目文件夹打开终端，重新构建并预览：

   ```
   npm run build
   npm run preview
   ```

6. 打开终端显示的地址（通常是 `http://localhost:4173/`）。如果页面没有变化，按
   `Ctrl + C` 停止预览，再运行一次 `npm run preview`。

## 4. 这个 Key 不是密码

`VITE_` 开头的变量会被打包进浏览器的 JavaScript 文件。任何人打开网页都能看到它。
所以：

- 它的安全依赖**域名白名单**和**配额**，不是靠保密。
- 不要把它当成密码保存，也不要在公开仓库里提交 `.env.local`。
- 真正需要保密的服务端密钥不属于这个项目；本项目没有后端。

## 5. 你会看到什么

| 情况 | 页面表现 |
| --- | --- |
| Key 有效 | 地图出现，两个机构标记（西安碑林博物馆、故宫博物院），标记旁注明「Unverified — secondary source」。 |
| Key 无效或被限制 | 显示错误面板和 `Try again` 按钮；错误代码可能是 `script-error` 或 `timeout`。 |
| 没有配置 Key | 显示 `Map not configured in this build`，不会向天地图发送任何请求。 |
| 地图加载失败 | 记录列表、搜索、详情、来源链接全部照常可用。 |

地图上的点只是**机构大致位置**，不是库房位置，也不是测绘坐标。这一点在页面上和
[map-pilot.md §3](map-pilot.md) 都有说明。

## 6. 请回报什么（不要发 Key）

- 浏览器名称和版本、操作系统、测试日期。
- 是否看到地图、是否看到两个标记。
- 开发者工具 Console 和 Network 里的报错截图（如果有）。
- 你当时是否在中国大陆的普通家庭/办公网络。
- 如果失败：错误面板上的 `code` 和 `message` 原文。

有了这些信息，才能把「本地代码正确」和「真实服务可用」分开记录。

## 7. 尚未核实的控制台细节

以下内容本次没有登录控制台验证，属于公开资料的说法，按页面提示操作即可：

- 是否必须先完成实名认证才能创建浏览器端 Key。

- `localhost` / `127.0.0.1` 是否必须加入白名单。
- 控制台菜单的准确名称和层级。

这些不确定性不影响你现在申请；如果某一步和本文不一致，以控制台页面为准，并把差异记下来。

## 8. 正式发布时（现在还不是这一步）

- `npm run build` 只是**预览构建**，不能用于正式发布。
- 正式发布只有一条命令：`npm run release`。它会先做严格数据校验，只要还有草稿记录就直接
  失败，并删除 `dist/`，避免误上传。
- 当前两条记录都还是草稿，所以 `npm run release` 现在**应当失败**，这不是故障。
- 等记录通过编辑复核后，再填写域名白名单、执行发布，并另做大陆网络测试。
