# 开通天地图：从注册到地图出现

这份说明写给不写代码的项目所有者。目标只有一个：拿到一个天地图「浏览器端」密钥（Key），
让页面显示真实底图。**不需要改代码，也不需要在对话里发送 Key。**

技术评估见[归档的 map-pilot](https://github.com/yang963852/beitie-atlas/blob/archive-pre-hygiene-2026-11-25/docs/map-pilot.md)，六种底图对比见[归档的 map-options](https://github.com/yang963852/beitie-atlas/blob/archive-pre-hygiene-2026-11-25/docs/map-options.md)。
本文只讲操作。

---

## 速查：五步

1. 注册天地图账号（手机号 + 邮箱验证）。
2. 申请成为「个人开发者」。
3. 控制台 → 应用管理 → 创建新应用 → 应用类型选 **浏览器端** → 复制 Key。
4. 项目根目录新建 `.env.local`，写一行 `VITE_TIANDITU_KEY=你的Key`，重启 `npm run dev`。
5. 运行 `npm run check:map-key` 确认可用，再打开 <http://localhost:5173/>。

全程约 10 分钟，不收费。

---

## 1. 注册与开发者身份

| 步骤 | 做什么 | 说明 |
| --- | --- | --- |
| 1.1 | 打开 <https://www.tianditu.gov.cn/>，点右上角「注册」 | 手机号、邮箱都要验证 |
| 1.2 | 登录后进入「开发资源 → 控制台」 | 也可从 <https://lbs.tianditu.gov.cn/> 进控制台 |
| 1.3 | 「申请成为个人开发者」，同意服务条款 | 个人即可，不需要企业资质 |

官方申请页把流程写成四步：注册用户 → 申请成为开发者 → 获取许可 Key → 使用 API
（<https://lbs.tianditu.gov.cn/authorization/authorization.html>）。

个人开发者升级为企业开发者可以在账号信息里改，不影响现在。

## 2. 创建应用、拿到 Key

1. 控制台 →「应用管理」（有的页面写「我的应用」）→「创建新应用」。
2. 填应用名称，例如 `beitie-atlas-local`；行业类别按实际选（文化/教育均可）。
3. **应用类型必须选「浏览器端」。** 选成「服务端」会拿到另一类 Key，网页里调用会被拒。
4. 域名白名单按下一节填写；本地调试可以先留空。
5. 提交后复制生成的 Key。它通常是一串 32 位字符。

## 3. 域名白名单怎么填

全国版[天地图应用控制台](https://cloudcenter.tianditu.gov.cn/)的白名单栏填写**纯域名**。本项目的公开站点填：

```
yang963852.github.io
```

要点：

- 域名不带 `https://`、路径或末尾的 `/`。多个域名用英文半角逗号分隔。
- 用于公开站点的浏览器端 Key 应限制到实际域名，并开启 **JavaScriptApi** 和**瓦片服务**。空白名单允许任意域名调用。
- GitHub Pages 的构建从仓库的 Actions secret `TIANDITU_BROWSER_KEY` 读取公开站点所用的浏览器端 Key。这个 Key 随网页交付给访问者，域名白名单用于限制它的使用范围。
- 本地调试可单独使用开发 Key。省级节点的表单格式可能不同，以实际使用的控制台提示为准。

## 4. 写进项目（不改代码）

1. 打开项目文件夹 `C:\Users\zhangyang\Desktop\AI_working\碑帖之间`。
2. 新建文本文件，文件名必须是 `.env.local`（前面有点，没有 `.txt` 后缀）。
3. 只写一行：

   ```
   VITE_TIANDITU_KEY=你的Key
   ```

   等号两边不要空格，不要加引号。
4. 保存。`.env.local` 已被 `.gitignore` 忽略，不会进入 Git。
5. **重启开发服务**：`Ctrl + C` 停掉原来的 `npm run dev`，再运行 `npm run dev`。
   环境变量只在启动时读一次，不重启不会生效。

## 5. 验证：先命令行，再浏览器

### 5.1 一条命令（能验证「类型」，不能验证「可用」）

```
npm run check:map-key
```

它只发一次地名搜索请求，不消耗瓦片配额，也不打印完整 Key。浏览器端 Key 的典型输出：

```
天地图密钥自检
  来源：.env.local
  密钥：96b6…d022 (32 位)
  探测：地名搜索（地理编码），关键词「西安碑林博物馆」

结果：Key 类型正确（浏览器端）。服务端接口按设计拒绝这次探测，不能据此判断有效或无效。

下一步：重启 npm run dev，打开 http://localhost:5173/ ，看地图栏是否出现底图。
```

**为什么不是「可用」**：天地图的服务端接口只接受「服务端」Key。浏览器端 Key 调它会被
拒绝（`301012`），这句拒绝恰好证明类型选对了。**浏览器端 Key 只能在浏览器里验证**，
也就是下面 5.2。

想先试一个 Key、不写文件：`npm run check:map-key -- --key 你的Key`。如果看到 `301001`
才是真的有问题（Key 写错或不存在）。

### 5.2 浏览器里看三件事

1. 打开 <http://localhost:5173/>，地图栏出现底图而不是说明面板。
2. 开发者工具 → Network，能看到 `api.tianditu.gov.cn` 的脚本请求和 `t0…t7.tianditu.gov.cn`
   的瓦片请求，状态码 200。
3. 地图右下角有服务商自己的版权与审图号标注；本项目不遮挡、不改写它。

### 5.3 想批量补坐标？还需要一个「服务端」Key

地理编码（地址转坐标）属于服务端接口，**浏览器端 Key 调不了**（会返回 `301012`）。如果
以后要用它批量补馆藏点位：

1. 在同一账号下再创建一个应用，应用类型选「服务端」；
2. IP 白名单填运行脚本那台机器的出口 IP（本机动态 IP 可先留空，但不要长期留空）；
3. 用它调用 `https://api.tianditu.gov.cn/geocoder`。

这一步现在不需要做：项目里 13 处机构还没有坐标，是证据问题，不是 Key 问题。

## 6. 报错对照表

### 6.1 服务接口返回 JSON

| code | 含义 | 先查什么 |
| --- | --- | --- |
| 301001 | 非法 Key | 复制是否漏字符/带引号；刚创建可等 1–2 分钟 |
| 301002 | 服务未授权 | 创建应用时是否勾选了所需的地图 API 服务 |
| 301012 | 这是浏览器端 Key | 正常现象：服务端接口只收服务端 Key。去浏览器里验证，别当成故障 |
| 301013 | 权限类型错误 | Key 类型与调用方式不匹配；或域名白名单挡住了无来源的请求 |

### 6.2 瓦片/网关返回 HTTP 状态码

来自官方帮助文档（<https://bingtuan.tianditu.gov.cn/docApi/dirlib/question.html>）：

| 状态码 | 含义 |
| --- | --- |
| 404 | token 为空 —— 请求没带 `tk` |
| 405 | 访问来源为空，无权限 —— 白名单没包含当前来源 |
| 406 | token 不存在 |
| 407 | 用户已冻结 |
| 408 | 当日配额已用完 / 被暂停访问 / IP 在黑名单 |
| 409 | 服务未授权 |
| 410 | 服务名与 token 不匹配 |
| 411 | 服务授权已过期 |
| 4121 | 请求头未携带来源信息 |
| 413 | 无法获取请求来源 IP |

### 6.3 页面上的三种状态

| 页面表现 | 含义 | 处理 |
| --- | --- | --- |
| 「如何启用真实底图」 | 构建里没有 Key，页面**不会**向天地图发任何请求 | 回到第 4 节 |
| 错误面板 +「重试」 | 脚本加载失败或 15 秒超时 | 看面板下方开发者信息里的 `code`：`script-error` 多为网络/域名拦截，`timeout` 多为网络不通 |
| `sdk-error` | 脚本加载了但没暴露 `T` 命名空间 | 多为 Key 被拒后返回了错误页；先跑 5.1 |

地图失败不影响其它功能：列表、搜索、详情、来源链接都照常可用。

## 7. 配额与费用

- 官方页面写明 JavaScript API 4.0「免费对外开放」，调用需要 Key。
- 官方申请页写明 2020 版起做**配额管理**，但没有公开每个 Key 的具体数字，需在控制台看。
- 第三方资料普遍写「个人开发者每个 Key 每天 1 万次请求、每个账号可建多个 Key」，
  **本项未在控制台核实**，按 1 万次/日做容量假设即可。
- 商用与高用量需要企业开发者协议；本项目是非商用开源项目。

对本站的实际影响：一次页面访问会加载若干瓦片，正常浏览远低于日配额；真正的风险是
Key 泄露后被别人盗用，所以**白名单比配额更重要**。

## 8. Key 不是密码

`VITE_` 开头的变量会被打包进浏览器 JavaScript，任何人打开网页都能看到。

- 它的安全依赖**域名白名单**和**配额**，不是保密。
- 不要把它当密码保存，不要提交 `.env.local`，不要贴到聊天或 issue 里。
- 本项目没有后端服务，也不需要服务端密钥。
