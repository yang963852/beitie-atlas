# Changelog

This file records formal editions. Merging a checked change to `main` deploys the site, but only the maintainer decides when that work becomes a formal edition. The live site may therefore include changes newer than the first version section below; the interface shows both the edition and the revision it was built from.

## v1.4.1 · 1.4.1 版

A release-integrity patch. It adds no corpus records and changes no public data format. The interface now shows the formal edition together with the build revision it was deployed from, so changes merged after an edition can be told apart from the tagged edition. Release metadata and formal tags are checked before publication, and the release manifest and downloadable library record the edition as `appVersion`. The eight works recorded under Unreleased are not part of this edition; they remain for the next minor edition.

### Added

- `npm run check:version` checks the package version, the npm lockfile and the matching CHANGELOG section. `npm run check:tag -- vX.Y.Z` additionally checks a formal tag against its own commit, edition and `main` ancestry.
- The release manifest and the downloadable knowledge-library ZIP now record the product edition as `appVersion` beside the source revision and corpus counts.

### Changed

- The interface footer, reading-room colophon and build details show the build revision with the formal edition, so a continuously deployed page is not mistaken for the tagged edition.
- The release runbook now defines semantic versioning, the continuous-deployment and formal-release split, the five release phases, and rollback rules.

## Unreleased · 未发布

Changes merged to `main` after v1.4.1. The release owner moves them into the next edition; a contributor does not need to edit this file for every pull request.

## v1.4.0 · 1.4 版

The 1.4 edition puts the copying reader first. Eight sourced close-reading notes were added to the 颜勤礼碑、兰亭序、九成宫醴泉铭、张迁碑、乙瑛碑、石门铭、瘗鹤铭 and 郑文公碑 paths. All 55 person pages now carry a bilingual “可临之作 / Works to copy” entry, naming linked works or stating when none is linked. Work reading cards gain a collapsed copying entry that brings together the surviving witness, close-reading notes and an evidenced calligrapher link, while keeping unknown and last-known locations distinct.

The edition also completes 19 exact work-to-person attribution links, raising the connected total to 91 of 180 entries without changing any attribution judgement. Twelve work dates now preserve the cited source wording, and a documentation gate rejects hand-written current edition numbers and stale README corpus counts. The three-section interface—编年 (Chronology), 访碑 (Atlas) and 读帖 (Reading room)—is in place, with the opening desk and chronology handscroll refined and one shared edition value read from `package.json`.

The corpus gained Huang Tingjian with two Northern Song letters, and Zhang Jizhi, Ouyang Tong and three Wei epitaphs. Counts: 133 works, 140 physical witnesses, 55 people, 47 places, 299 sources, 96 events and 24 notes. [Knowledge library](knowledge/README.md) · [Status report](docs/knowledge-status.md)

## v1.3.0 · 1.3 版

The 1.3 edition fills five gaps in the library's cast. New person pages carry Zhong Yao, Yu Shinan, Chu Suiliang, Yang Weizhen and Wang Chong, each with the works that survive and the evidence behind them; nine works and seven physical witnesses join the corpus, from the Tongzhou recension of the Sacred Teaching Preface of 663 to Wang Chong's poem leaf for a disciple. Attribution doubts are recorded rather than resolved: the Tongzhou stele stays marked as attributed because Gu Yanwu dated it five years after Chu Suiliang's death, and Liu Jiuan's doubt about Wang Chong's Baoshan album stands beside the museum's own attribution. Works now link back to their calligraphers throughout the Tang entries, and the Yan Zhenqing page carries its family shrine stele again. The edition also stops tracking the compiled interface: `data/index/knowledge-v1.json` is generated by `npm run knowledge:build`, which `dev`, `build`, `check`, `typecheck` and `test` run themselves, so a clone no longer carries a generated file that conflicts on every content change; the GitHub catalogue and `knowledge/README.md` stay tracked as the reader-facing projection. Counts: 126 works, 133 witnesses, 46 places, 201 sources, 75 events. [Knowledge library](knowledge/README.md) · [Status report](docs/knowledge-status.md)

## v1.2.0 · 1.2 版

The 1.2 edition makes the library easier to edit and easier to query without changing the published data interface. Authors now write flat `schemaVersion: 2` properties, so every record can be edited in Obsidian's property panel; `knowledge/` is the vault and ships its record templates, property types and reading CSS, while per-machine state stays ignored. Search matches every term across a record's titles, aliases, calligraphers, places and catalogue number, so terms may come from different fields. Two tools serve contributors and agents: `npm run knowledge:query` prints one record with its sources, and `/llms.txt` summarises the site, data and rights for machine readers. The compiled interface remains `beitie-knowledge/1`, and the release gate is unchanged. [Knowledge library](knowledge/README.md) · [Engineering decisions](docs/engineering-plan.md)

## v1.1.0 · 1.1 版

The 1.1 edition publishes the whole library: 117 works, 126 physical witnesses, 46 places, 184 sources and 75 provenance events. Every record passes the release gate, so the draft state, the per-entry review labels and the preview draft notice no longer appear to readers. Editorial uncertainty stays in each record's 待考 and claims sections, not in workflow notes. The version is shown as 1.1 on the site. [Knowledge library](knowledge/README.md) · [Status report](docs/knowledge-status.md)

## v0.2.0-beta.1 · 内部测试第一版

The public Pages preview adds a Markdown knowledge library for readers and contributors, with Yan Zhenqing and Shen Yinmo as the first person-led reading paths. Works and physical witnesses retain distinct identities and sources. Contributors can submit evidence in Chinese directly on GitHub, or claim a small web task and hand it to their local agent. The coordinator decides merges. The beta accepts drafts and has its own feedback form.
